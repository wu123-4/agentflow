# 01 · 需求文档（PRD）— AgentFlow Agent Harness 基础设施

## 1. 产品定位

AgentFlow 是一个**Agent Harness（智能体运行时控制系统）**。核心叙事：**Agent = Model + Harness**——模型能力是给定的，Harness 的工程深度决定 Agent 能否在生产环境存活。

它不是"聊天壳"，而是把**权限、状态、副作用与完成证明从模型手中转移到确定性运行时**：模型可以自由选择如何解决问题，但不能自行扩大权限、信任过时状态、或从一段有说服力的摘要中宣布成功。

- **任务契约先行**：Agent 启动前显式定义产出、风险上限、工具范围与资源预算
- **确定性权限边界**：模型决定"做什么"，契约和代码决定"能不能做"
- **工具能力可扩展**：任何符合 MCP 协议的服务即插即用
- **执行过程透明**：用户可看到智能体的推理、工具调用、权限裁决与中间状态
- **完成可证明**：任务是否完成由门控代码判定，而非模型自评

**一句话**：把"LLM + 确定性运行时控制 + 标准化工具生态"封装成可交互、可观测、可控的 Harness 基础设施。

## 2. 目标用户

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 终端用户 | 使用对话完成任务的知识工作者 | 快速获得结果，理解 Agent 在做什么 |
| 智能体配置者 | 定义 Agent 人设、绑定工具与 MCP Server 的运营/开发者 | 低代码配置能力与工具组合 |
| 平台管理员 | 部署与维护平台的工程师 | 可观测、可恢复、成本可控 |

## 3. 功能需求

### 3.1 对话与会话管理（P0）

- FR-1 用户可创建/重命名/删除会话；会话列表按更新时间排序
- FR-2 消息支持 Markdown 渲染、代码高亮
- FR-3 回复以流式（SSE）逐 Token 呈现，并展示"正在思考/正在调用工具"等状态
- FR-4 会话可中断生成（Stop）与重新生成（Regenerate）
- FR-5 历史消息持久化，刷新/重开后完整恢复

### 3.2 智能体工作流（P0）

- FR-6 Agent 基于 LangGraph 状态图运行：意图路由 → LLM 决策 → 工具调用 → 观察 → 继续/结束
- FR-7 支持多轮工具调用（ReAct 循环），并设置最大迭代次数防止失控
- FR-8 工作流状态通过 Checkpointer 持久化：服务重启后可从断点恢复会话
- FR-9 支持"反思节点"：工具结果不佳时自动重试或换策略（可配置开关）

### 3.3 MCP 工具生态（P0）

- FR-10 平台可作为 MCP Host，连接多个 MCP Server（stdio / SSE / Streamable HTTP 传输）
- FR-11 管理员可注册、启用/禁用 MCP Server；工具列表自动发现并注入 Agent
- FR-12 内置常用 MCP Server：文件系统、Web 搜索、数据库查询（示例：SQLite/Postgres）
- FR-13 工具调用结果以结构化卡片展示（输入参数、输出、耗时、状态）

### 3.4 人机协同 HITL（P1）

- FR-14 可标记某些工具为"高风险"（如写操作、删除、外发消息）；触发时图执行暂停（`interrupt`），前端弹出确认卡片
- FR-15 用户可选择：批准 / 编辑参数后批准 / 拒绝；拒绝后 Agent 调整策略继续
- FR-16 确认请求超时（默认 10 分钟）自动视为拒绝

### 3.5 记忆与上下文（P1）

- FR-17 会话内上下文自动裁剪（按 Token 预算保留最近消息 + 摘要）
- FR-18 跨会话长期记忆：重要事实写入 pgvector，对话时语义检索召回
- FR-19 用户可查看与清除长期记忆条目

### 3.6 多模型与配置（P1）

- FR-20 通过 LangChain 抽象支持多家模型供应商（OpenAI、Anthropic、兼容 OpenAI 协议的本地模型）
- FR-21 管理员可配置默认模型、温度、最大 Token；用户可在会话级覆盖模型

### 3.7 可观测与管理（P2）

- FR-22 记录每次运行的节点轨迹、工具调用、Token 用量与耗时
- FR-23 提供运行监控页面：会话维度的执行时间线
- FR-24 错误统一上报与友好提示（LLM 限流、MCP Server 掉线等）

### 3.8 Harness 工程核心（P0，Phase 1 已交付）

- **FR-25 任务契约（Task Contract）**：每次 run 可显式携带契约——`outcome`（期望产出）、`max_risk`（允许的最高工具风险等级）、`allowed_tools`/`denied_tools`（工具白/黑名单）、`budgets`（max_tokens / max_tool_calls / max_iterations）、`gates_enabled`（完成门控开关）；契约经 pydantic 校验，非法字段直接 422；契约随 run 落库并随图状态持久化，中断恢复后仍生效
- **FR-26 确定性权限控制（AuthorityController）**：每次工具调用在执行前经运行时代码裁决——黑名单/白名单外/风险超契约/超工具预算 → **DENY**（100% 不执行，拒绝原因回喂模型引导换策略）；契约内高风险 → **REQUIRE_HITL**（人工确认）；其余 → **ALLOW**。权限校验不在模型手里
- **FR-27 完成门控（CompletionGate）**：run 自然结束时由确定性代码评估完成条件——输出非空、工具调用成功率 ≥90%、token 与工具调用未超契约预算；任一不通过则 `stop_reason=gate_blocked`，不允许模型自评宣布成功；门控结果随 run_finished 事件下发
- **FR-28 预算强制（Budget Enforcement）**：token 消耗实时对照契约预算，超限**干净终止**（`stop_reason=budget_exceeded`，检查点已持久化可续跑）；工具调用次数在调用前拦截；迭代轮数超契约上限强制结束

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首 Token 响应 < 2s（不含 LLM 排队）；单实例并发会话 ≥ 50 |
| 可用性 | MCP Server 故障不影响纯对话能力；优雅降级 |
| 安全 | API Key 仅存服务端；高风险工具默认需确认；SQL 工具只读优先；输入长度与频率限制 |
| 可扩展 | 新增 MCP Server 零代码；工作流图节点可插拔 |
| 可恢复 | 检查点保证中断可续跑；会话数据不丢失 |
| 合规 | 对话数据可导出与删除（用户主权） |

## 5. 核心用户故事

- **US-1** 作为用户，我说"帮我总结这份 PDF 的要点"，Agent 调用文件读取 MCP 工具拿到内容，流式返回总结，并能看到它读了哪个文件。
- **US-2** 作为用户，我说"查一下 orders 表昨天的订单量"，Agent 调用数据库 MCP Server 执行只读 SQL 并返回结果与 SQL 语句。
- **US-3** 作为用户，我说"删除临时目录里的旧文件"，Agent 准备执行写/删操作时弹出确认卡片，我批准后才真正执行。
- **US-4** 作为配置者，我在管理页新增一个"Web 搜索 MCP Server"，保存后所有 Agent 自动获得 `search` 工具。
- **US-5** 作为管理员，服务重启后用户的会话仍能从上次中断处继续，而不是丢失上下文。
- **US-6** 作为用户，我在设置里把模型从 GPT 切换到本地模型，后续对话立即生效。
- **US-7** 作为用户，我下达"只做调研、不允许修改任何文件"的任务（max_risk=low 契约）；即使模型试图调用写工具，Harness 也 100% 拦截并把拒绝原因回喂，模型改用只读方式完成调研——**整个过程不需要我盯着**。

## 6. 范围外（本期不做）

- 多租户与复杂权限体系（仅单用户/轻量团队）
- 计费、订阅系统
- 工作流可视化拖拽编辑器（文档预留扩展点）
- 移动端原生应用（Web 响应式覆盖）

## 7. 验收要点（MVP）

1. 端到端跑通：React 发消息 → LangGraph 执行 → MCP 工具调用 → 流式回答
2. 至少接入 2 个真实 MCP Server（文件系统 + 搜索/数据库任一）
3. 一次 HITL 确认流程完整可用（中断 → 确认 → 恢复）
4. 会话刷新后可恢复，检查点续跑成功
5. 工具调用卡片正确展示参数、结果与耗时
6. Harness 验收（Phase 1，已通过 harness_check 8/8）：
   - 越权调用（契约 max_risk=low 时尝试 high 工具）**100% 拦截**，拒绝消息回喂模型
   - token 预算超限干净终止（budget_exceeded + 检查点保留）；工具/迭代预算调用前拦截
   - 空输出被完成门控拦截（gate_blocked），门控关闭时行为不回退
   - 非法契约 API 422；契约随 run 落库、跨进程重启后恢复仍生效
