## Harness Phase 2 · 可观测性（✅ 已交付）

**目标**：Harness 行为可度量、可归因。

**Node Execution Pipeline**：`Tracing → Budget → Policy → 节点逻辑 → CompletionGate → Checkpoint`。

- **Tracing**：`app/observability/` 双通道 span 导出——始终挂内存环形缓冲（按 run_id 归集，供 `/traces/{run_id}` 与验收断言），配 `OTEL_EXPORTER_OTLP_ENDPOINT` 时同时 `BatchSpanProcessor` 导出 OTLP→Jaeger（docker-compose 内置 `jaeger`，4318/16686）。span 采用事件流驱动（零图改动，D8 安全）：workflow 根 span + 节点 span（agent/authority_gate/wait_approval/tools）+ 工具 span + 模型 span，属性遵循 OTel GenAI 语义约定（`gen_ai.operation.name`/`gen_ai.request.model`/`gen_ai.tool.name`/`gen_ai.usage.*`）。
- **Budget**：`app/harness/budget.py` 的 `BudgetTracker`（`threading.Lock` + `contextvars` 隔离并发 run）；runtime 从 `Run.usage` 播种（resume 后累计），`agent_node` 读取剩余预算注入**瞬态** system 提示（Agent 主动收敛）；超限仍由 runtime 干净终止（D10，绝不抛异常）。
- **Policy**：`app/harness/policy.py` 的 `astream_with_policy`——tenacity 指数退避重试（仅瞬态异常）+ 单模型重试耗尽后按 `MODEL_REGISTRY.fallback` 降级；**仅在尚未产出 chunk 时允许重试/降级**（不重放已下发 token）。
- **注册表**：`GET /models`（配置驱动 `MODEL_REGISTRY`，provider 由 `resolve_provider` 单一来源解析）；`GET /sessions/{id}/runs` 运行轨迹（聚合既有表，无新表）。

**验收（已通过 16/16）**：`scripts/phase2_check.py` 断言 span waterfall 与 parent 关联、预算快照、`budget_exceeded` 回归、tenacity 重试不降级、fallback 链（`deepseek-chat → qwen-plus`）+ `fallback` SSE 事件、`/models`、运行轨迹、会话级模型覆盖；`harness_check`（14/14）、`e2e_check`、`m3_check`（14/14）回归全过。

## Harness Phase 3 · 恢复与熵管理（✅ 已交付）

**目标**：失败可恢复、长任务不劣化。

- 分级恢复策略：`app/harness/recovery.py` 的 `execute_with_recovery`——工具瞬态失败（超时/连接）→指数退避重试；**不确定的写操作先对账副作用再决定是否重试**（检查目标状态是否已落地，已落地视为成功）；模型限流/不可用→切 fallback 链（Phase 2 Policy 承接）
- 循环检测：`graph.py` 对实际执行调用做 action+params 哈希滑窗比对，连续重复自动终止；runtime 下发 `stop_reason=loop_detected`
- Context Reset 双策略：`app/harness/context.py` 的 `maybe_govern`——Compaction（旧消息摘要压缩，保留近期窗口）+ Reset（超长历史截断），治理事件经 `context_events` state 转 `context_compressed` SSE 事件
- 契约 `invariants` 字段消费：`gates.py` 评估 `no_denied` / `denied<=N` / `requires_tool:name` / `tool_success_rate>=X`（含跨轮历史拒绝计数）
- 验收脚本 `scripts/phase3_check.py`

**验收（已通过 13/13）**：故障注入（工具瞬态失败/不确定写/循环重复/上下文超长）下恢复成功率 100%；`loop_detected` 干净终止；Compaction/Reset 事件与摘要替换正确；invariants 违规触发 `gate_blocked`；`harness_check`（14/14）、`phase2_check`（16/16）、`e2e_check`、`m3_check` 回归全过。

## 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| LangGraph interrupt/checkpoint 语义版本变动 | HITL/契约恢复返工 | 锁定版本；spike 先行（已完成 1.2.14 验证） |
| MCP stdio 子进程管理复杂（僵尸/重启） | 工具不稳定 | 统一 ClientPool 封装 + 进程监督 + 超时 |
| 大工具结果撑爆上下文 | 成本与延迟 | 强制 preview + 分页读取工具设计 |
| Prompt 注入经工具结果生效 | 安全 | 标记包裹 + 契约权限裁决 + 只读账号 |
| SSE 经代理被缓冲 | 流式失效 | `X-Accel-Buffering: no`；心跳事件；预留 WebSocket 退路 |
| 契约过严导致正常任务被误拦 | 任务完成率下降 | 默认契约不收紧；拒绝原因必须回喂模型引导换策略；评估集含正常任务回归 |
